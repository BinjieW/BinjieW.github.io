Benchmark setup and results

Hardest-10 benchmark.

Hardest-10 is used for both the main model comparison and the feedback experiments. It contains 10 source objects, 6 difficulty levels, and 4 edits per level: 240 edit requests per model.

Difficulty gradient

Six qualitatively different kinds of edit.

The levels adapt the SOLO taxonomy: difficulty grows with how many code regions and artifact relationships must be understood together—not simply with prompt length.

Level 1 · Unistructural

Single parameter

Change an explicit color, size, position, or rotation value already present in code.

Level 2 · Unistructural

Single component

Coordinate a loop, primitive type, or local spatial rule within one component.

Level 3 · Multistructural

Multiple components

Apply several independent changes across different code blocks without interference.

Level 4 · Relational

Topology & structure

Add holes, merge geometry, or integrate new features with existing object relationships.

Level 5 · Relational

Semantic restyling

Interpret an abstract style while preserving the original object’s recognizable identity.

Level 6 · Extended abstract

Scene composition

Build multiple new objects, environmental context, plausible scale, lighting, and relations.

Notes from manual verification of the current framework

Manual verification identified several recurring issues: some Level 1 changes are visually small or normalized away; RGB renders cannot directly verify metadata or topology in some Level 3–4 tasks; and later levels are more sensitive to occlusion, execution success, and semantic judgment. We plan to address these issues in the next benchmark version.

Highest observed scores

Opus 4.8 (0.752) and Sonnet 5 (0.727) lead overall, with especially strong L5 scores and high execution success.

Render success

The baseline contains 402 render failures. These tasks receive zero in the current aggregate score and are reported separately in the execution column.

Level 1 manual check

Manual inspection found that many observed zeros completed the intended code-side change, but the change was not visible enough in the six rendered views.

Level 6 tasks

Level 6 combines multiple requirements, including object completeness, relative scale, spatial relationships, visibility, and overall scene composition.
