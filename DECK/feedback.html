Experiment A · Execution feedback

Blender errors as feedback.

Each initially failed script receives its Blender error and can be revised for up to ten rounds. The experiment measures render recovery only—not whether the repaired artifact is semantically correct.

What remains after ten rounds?

Only six cases: repeated use of unsupported Blender APIs in five cases and one persistent timeout. Most gains arrive before round three.

Interpretation boundary

Execution recovery proves that the artifact can be produced. It does not prove the requested geometry, style, or scene relation is correct; quality must be measured separately.

Experiment B · Quality feedback

Six quality-feedback conditions.

Non-perfect, successfully rendered outputs can iterate for up to ten rounds. After each round, a VLM judge (Sonnet 5) evaluates the checklist from six rendered views. The aggregate score averages all 240 tasks per model and counts render failures as zero.

Model heterogeneity

Results differ by model.

Aggregate scores increase in most conditions, while individual models respond differently to the same feedback.

Claude Opus 4.8

Highest result with verdicts + renders: 0.752 → 0.923 (+0.171), reaching full score on 218 / 240 tasks.

Claude Sonnet 5

Highest result with per-item verdicts alone: 0.727 → 0.947 (+0.220). Adding renders did not improve the final mean further.

Claude Sonnet 4.6

Render-only is roughly neutral (+0.001); every other condition lowers the aggregate score, partly through reduced render success.

Note on the current feedback setup

Checklist-based feedback and final scoring currently use the same benchmark rubric and VLM judge (Sonnet 5). These experiments therefore report improvement under the current setup. A later experiment will use a separate feedback signal.
